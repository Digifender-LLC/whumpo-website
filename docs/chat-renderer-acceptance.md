## All five original acceptance criteria

1. **Registered version and readable history:** the protocol closes template/type/binding shapes, verifies immutable digests and requires current client capabilities. The client refuses unsupported active templates. The current historical projection is separately validated, contains literal facts and no active approval authority. The 69-case contract and strict history suites passed again during this audit; unsupported live client capability returned 409.
2. **Intended change and server-only review authority:** submitted text maps to current content IDs/revision, with validation before compilation. Preview preparation does not save or publish. Local connected checks and the live test release verify the intended text, private preview and exact reviewed save, with zero publications. Existing `ChatControl` metadata retains approval authority.
3. **Reload/navigation/dismissal:** the connected local browser covers lost draft/submission responses, same-ID recovery, navigation/collapse, account fences, closed reload and dismiss/resume from history. The live browser verifies saved-draft reload and exact receipt replay. No read/render/resume automatically resends an effect or reopens a dismissed dialog.
4. **Inspected keyboard/screen-reader/mobile evidence:** the full built-workspace browser checks both Tab directions, arrow-key choices, error focus, cancellation/return, dialog entry/close, late-reply focus custody, zoom/reduced motion and 360/390px geometry. The isolated real Orca runner supplies seven inspected speech-generation checkpoints. Mobile keyboards are explicitly simulated, including visual viewport scrolling and layout viewport resizing; the live 390px Chromium screenshot is inspected. Evidence details and artifacts are in [verification](verification.md#chat-mobile-viewport-and-screen-reader-evidence--october-2-2026-utc).
5. **Truthful disclosures/recovery/history, current-only rendering:** current status distinguishes answers, previews, exact saves, unresolved work and held uploads. Discard/removal does not falsely retain answers; upload-view history does not imply a completed upload. Unknown versions refuse; labels/answers render as text, with no model HTML/code or old-schema decoder. Protocol, history, recovery, upload and connected browser assertions cover these boundaries.

Both TypeScript/compiler checks, build, focused Chat reply/delivery and customer-site regressions passed on the unchanged runtime. [The four-Worker test release](chat-test-release.md) independently verifies the current schema/assets/bindings, signed HTTP and live Chromium journey. Source/test evidence is inspected rather than inferred from issue closure or a single green command.

## Completion and boundaries

WH-107 is complete to its original implementation and inspected-evidence scope. Earlier checkpoint notes incorrectly made physical-device/human acceptance a prerequisite of this renderer packet. Its verification explicitly requires reporting fixture versus device scope; it does not require a named physical device or a consenting-customer study. The broader real-device, human assistive-technology and customer acceptance remain explicit in WH-024 and WH-112. Automated Orca speech generation is not human listening; viewport emulation is not a physical phone keyboard.

WH-108 still owns bounded custom composition, semantic question admission, prose-to-proposed-answer corrections and receipted model continuation; WH-109 owns persistent views; WH-110/111 own routine-journey/navigation work. Generic photo-bearing custom answers require their full domain/lifecycle admission before activation, independently of the delivered maintained uploader and shared field control. Off-device key custody, whole-platform recovery, model quality and launch gates remain open. No device/customer/whole-product completion is claimed, and CSAM, Daybreak and CMS testing stay deferred.
