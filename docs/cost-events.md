## Purpose and authority

Real usage and provider costs must be reconcilable *before* customers are charged for anything. A cost event is **evidence about what the platform consumed or owes**. It is never authority to charge, credit, admit, throttle or enforce:

- **No billing authority.** `customerUnits` is the constant `0` in version 1, and any field that names a unit, debit, credit, charge, balance, wallet, entitlement, price or invoice is refused. Customer debits, premium funding and entitlement stay in the WH-042/043/044 ledgers; this ledger has no reserve, debit, credit or grant operation.
- **Standard AI stays internal.** Standard assistance records `aiTier: "standard"` with zero customer units. A premium gateway attempt records its provider cost, and its customer debit stays in the gateway buckets ([`customer_actual`](../src/gateway-spend.ts)); the event never repeats that figure.
- **Shadow is not expense.** The Muse `subscription-shadow` estimate ($0.10/$0.20 per million tokens in [`museTestRate`](../src/model-policy.ts)) is hypothetical. It is reported in its own bucket and never counted as provider expense or compared with an invoice.
- **Evidence for the fair-use Monitor, not a trigger.** [Fair-use](pricing-and-model-policy.md#unlimited-standard-ai-under-fair-use--september-29-2026-decision) enforcement stays disabled; events feed [company finance review](company-finance-review.md) and WH-023 only.
- Visitors, deterministic jobs and view rendering never invoke the owner maintainer to produce or repair an event ([composition architecture](roadmap/composition-architecture.md)).

## Envelope, version 1

A cost event is a closed JSON object. Unknown, missing or billing-, locator-, content- or client-time-shaped fields are refused with a specific code. There is no reader for other versions ([current-version policy](current-version-policy.md)).

| Field | Rule |
| --- | --- |
| `contractVersion` | Exactly `1` |
| `source` | Registered producer (`inference-receipt`, `gateway-settlement`, `storage-operations`, `cloudflare-usage-import`, `liability-register`, `notification-delivery`, `connector-call`). A source may emit only its registered dimensions |
| `sourceEventId`, `providerEventId` | Producer-stable identifier (≤128 characters of `[A-Za-z0-9._:-]`) and the provider's own event/log ID when one exists. Both are preserved verbatim across placement and tariff changes; the provider ID may be learned by a later revision (`null` → value) but is never replaced or dropped. Account closure is the only operation that removes either (see *Privacy, retention and closure*). The prefix `closed:` is reserved for closure tombstones and refused on input (`INVALID_EVENT`) |
| `revision` | Integer ≥1, monotone per identity. A later revision replaces an earlier one; it never adds to it. Revisions may only **advance** (see *Revisions* below) |
| `idempotencyKey` | Must equal SHA-256 of canonical `{dimension, source, sourceEventId}`. Producers cannot invent keys |
| `kind` | `usage` (metered) or `liability` (non-metered cost: floors, minimums, licenses, renewals, support, retained staging, uncertain operations); fixed by the dimension |
| `dimension`, `workload` | Closed registry entries (below) |
| `workClass`, `taskRef`, `attempt` | `task`, `retry`, `control` (acknowledgments, safety, reconciliation, orchestration) or `standing` (no task). Task, retry and control cost names its opaque task and stays a separate line; retry is attempt ≥2; standing cost has no task |
| `attribution` | Tenant `{scope:"tenant", ownerId, projectId|null, resourceId|null}` using WH-071 stable IDs, or `{scope:"platform", pool}` (`shared-account`, `control-plane`, `closed-account`). Physical locators (database, bucket, script, namespace, gateway, account ID, hostname, URL) are refused |
| `placementClass` | Label only (`static`, `shared-api`, `isolated-function`, `persistent-process`, `platform`), as of `occurredAt`; it is not part of identity or tariff selection |
| `quantity` | `{state:"known", value, unit}` with a non-negative safe integer in the dimension's fixed unit, or `{state:"unknown", reason}`. Every money, quantity and exposure figure is an integer no larger than `Number.MAX_SAFE_INTEGER` |
| `cost` | One of five bases, below. Money is integer USD microdollars |
| `outcome` | `settled`, `pending`, `uncertain` or `released`; `released` consumed nothing: known quantity `0`, a known cost of `0` and no non-zero detail (token counts) |
| `customerUnits` | Exactly `0` |
| `aiTier` | `standard`, `premium` or `null`; non-null only for `ai.*` dimensions |
| `detail` | Closed per-dimension integer map (for `ai.inference.call`: `inputTokens`, `outputTokens`); no free text |
| `occurredAt`, `observedAt` | UTC millisecond timestamps; `observedAt ≥ occurredAt`. The ledger adds `receivedAt` and a receive sequence itself; a producer-supplied value is refused |

Cost bases: `tariff` (the ledger prices a *known* quantity from a pinned `{id, version}` tariff), `receipt` (the source computed it from an immutable rate snapshot), `provider-reported` (a provider, gateway or invoice figure), `shadow` (hypothetical inference estimate, `ai.*` only) and `unknown` (`reason` from a closed list plus `exposureMicros`, an upper bound or `null` for unbounded). Free text never appears: reasons are `rate-missing`, `usage-not-reported`, `usage-pending`, `outcome-unknown`, `provider-lag`, `unpriced`, `not-measured`, `invoice-pending`, `entitlement-unknown`.

Only `provider-reported` is ever "actual provider expense". `tariff`, `receipt` and `provider-reported` together are the **known estimate** used for reconciliation; `shadow` is reported separately; `unknown` is counted, never summed as zero.

## Append rules

| Situation | Rule |
| --- | --- |
| Duplicate / redelivery | Same key, revision and content: no-op (`duplicate`). The same key and revision with different content: `IDEMPOTENCY_CONFLICT`, nothing written. Adapters derive `observedAt` and `placementClass` from the source row so a redelivery reproduces the stored bytes |
| Delayed / out of order | Aggregates use the highest revision per identity, so any arrival order converges (the suite replays 31 orders of the producer revisions and all 6 orders of an unknown → tariff → provider-reported chain). A lower revision arriving later is stored for audit as `stale-revision` and not counted. Receive sequence, not event time, orders arrival |
| Revision compatibility | Every pair of revisions of one identity must be compatible, checked symmetrically, so a contradictory pair is refused whichever arrives second and a valid set converges in any order. **Fixed by the first revision** (`IMMUTABLE_FIELD`; `TENANT_MISMATCH` for attribution): `workload`, `workClass`, `taskRef`, `attempt`, `placementClass`, `occurredAt` (so a revision can never move cost to another period), `aiTier` and `attribution` (owner, project and resource, or the platform pool); a provider ID once known — the owner, project, resource, task and provider IDs are compared through keyed digests taken at append, so the same pair is refused with the same code before and after account closure; and the pinned tariff `{id, version}` once any revision was priced under it (a revision cannot reprice, but may replace a tariff estimate with a `receipt` or `provider-reported` actual). **May advance** (`REVISION_REGRESSION` when it goes backwards): `quantity` and `cost` from unknown to known and a known value to a newer known value, `outcome` `pending` → `uncertain` → `settled`/`released` (a terminal outcome is final), `observedAt` forward, and the provider ID from `null`. A known quantity or cost is never made unknown again |
| Late for a closed period | Accepted, flagged `lateAfterClose`, and reported as a **restatement** with its delta. `closePeriod` is idempotent: the first call fixes the snapshot and every later call returns that same snapshot, so a closed snapshot and the baseline of its restatement are never rewritten |
| Tenant mismatch | The registered owner of `projectId` must equal `ownerId`, and the resource must belong to that project; otherwise `TENANT_MISMATCH` and no write. Unknown project: `UNKNOWN_PROJECT`. A later revision cannot move cost to another owner. A closed project is `PROJECT_CLOSED`: late provider cost is recorded at `platform/closed-account` scope instead. A same-revision redelivery that changes attribution is `TENANT_MISMATCH`, not a duplicate, before and after closure |
| Closed-account ingress | An event at `platform/closed-account` scope is canonicalised on ingress exactly as closure canonicalises a stored one (opaque keyed source/idempotency identity, `taskRef` and `providerEventId` cleared, cost reference pseudonymised), so a producer re-emitting after `PROJECT_CLOSED` leaves no project, task or provider ID in the ledger. It is the same identity as the closed tenant event of the same `{source, sourceEventId, dimension}`: a redelivery is a no-op and a later revision converges on it. An identity first recorded at closed-account scope has no provable owner, so a tenant emission of it is refused (`TENANT_MISMATCH`), and a closed-account emission of an identity that is still open at tenant scope is refused too; nothing is written in either case |
| Unknown rate or quantity | A `tariff` event naming an unknown or unpriced tariff is refused (`UNKNOWN_TARIFF`, `UNPRICED_DIMENSION`). The producer records `cost: unknown, rate-missing` instead; it is counted as unknown with its exposure and keeps reconciliation `incomplete` |
| Pending or uncertain operation | Must carry `cost: unknown` with the reserved hold as `exposureMicros`. It becomes known only through a later revision (`settled` or `released`). A lost response is never retried and never priced as zero |
| Released reservation | Quantity known `0`, cost known and exactly `0` for every basis, token detail `0` or absent (`OUTCOME_COST` otherwise); it consumed nothing |
| Tariff pinning | The event keeps the tariff `{id, version}` it was priced under, which must be effective at `occurredAt`. Publishing a later tariff, or moving the resource to another placement class, never reprices it |
| Account-wide allowance | Tariff cost is marginal. A free allowance is metadata of the *account* and may not be allocated to tenants (`ALLOWANCE_ALLOCATION`); two tenants each under the allowance both carry marginal cost, and the difference to the invoice appears as an account-level residual |
| Rounding | Cost is held as an exact fraction and rounded up **once per reported total**, so splitting usage into many events cannot raise a total (the scenario calculator's "partitioning cannot inflate" invariant) |
| Exact integers | Totals are summed exactly; a quantity, money, exposure, residual or period delta beyond `Number.MAX_SAFE_INTEGER` makes the report refuse with `AMOUNT_UNSAFE` rather than round (two valid shadow amounts of `9007199254740991` and `2` are individually accepted and their report is refused, never shown as `…992`). The check depends only on the set of current revisions, so it does not depend on arrival order. A reconciliation tolerance must be a non-negative safe integer (`INVALID_TOLERANCE`) |
| Isolation | The ledger stores its own copy of every accepted event, prices from a frozen snapshot of the registry taken at construction (a later edit of the caller's registry object cannot reprice pinned history; the exported registries are frozen) and returns fresh copies from every read (`exportHeads`, `summary`, `restatement`, `closePeriod`) |
| Content and secrets | Content-, secret- and token-shaped values, free text and locator-shaped keys are refused; the suite scans canonical bytes for secret patterns |

## Aggregation and reconciliation

`summary` reports, per period, owner or pool, and by dimension, work class and workload: units, the tariff/receipt/provider-reported/known-estimate/shadow microdollars, unknown event and unknown-quantity counts, bounded exposure, unbounded-exposure events, pending and uncertain counts and zero customer units. Keys are sorted, so reports do not depend on arrival order. Figures are exact integers (see *Exact integers*).

`reconcile(period, invoice)` compares an authenticated provider invoice (provider, invoice ID, period, USD total, line sums) with the events for that provider and returns the invoice total, known usage, known liabilities, the excluded shadow total, an explicit signed **residual**, unknown and unfinished counts, bounded and unbounded exposure and late-after-close count. The residual, line sums and exposures are computed exactly and a figure beyond the safe-integer range is refused, as is a malformed tolerance. Status is `incomplete` while anything is unknown or unfinished, `reconciled` only when the residual is within the stated tolerance, and `unexplained-residual` otherwise. A negative residual is account-level upside (shared allowance, credit or rounding), never a tenant credit; floors, provider minimums, licenses, renewals, support and staging appear as liability lines rather than being allocated silently to tenants. The reference does not import invoices; WH-171 owns the import.

## Privacy, retention and closure

Events are **content-free**: no prompts, replies, emails, free text, source, credentials or physical locators. The task reference is opaque; the owner/project/resource IDs and the producer's source and provider IDs (which can embed a project UUID, for example the storage reading `<projectId>:<period>:read_ops`) are the only linkage. A new lifecycle class `cost-events` (purpose: reconciling provider cost; readers: operators; deletion and export boundary; key custody) must be registered in [data lifecycle](data-lifecycle.md) and [data protection](data-protection.md) by WH-170 before a table exists; the existing short operational windows are not extended silently.

**Closure boundary (`redactOwner`).** Clearing the attribution alone would not unlink an event, because `sourceEventId`, `providerEventId`, `taskRef`, the cost `ref` (a free producer string that can carry a project or owner UUID) and the SHA-256 `idempotencyKey` (a hash of guessable inputs) would still name the owner's records. On closure the reference therefore, for every revision of every identity of the owner:

- replaces attribution with `platform/closed-account`, clears `taskRef` and `providerEventId`, and replaces each cost `ref` with a keyed pseudonym `closed:<32 hex>` (the same reference always maps to the same pseudonym; the version 1 contract has no class of "public catalogue" reference, so none is kept);
- replaces `sourceEventId` and `idempotencyKey` with an opaque tombstone `closed:<32 hex>` derived with HMAC-SHA-256 under a **closure key** held by the ledger (not the event rows), and re-derives the idempotency key from it so the derived-key rule still holds. The ledger copies the key once at construction (a `string` or `Uint8Array` of at least 16 encoded bytes; anything else is `INVALID_CLOSURE_KEY`), so a caller editing its own buffer afterwards cannot change any digest;
- keeps, per revision, only keyed digests of what it erased — of the delivered event, and of its task and provider IDs — and, per identity, a keyed digest of its attribution. They exist from the first append, so revision and redelivery checks give the same answer after closure as before; they reveal nothing without the key;
- remembers only the keyed digest of the closed owner (to refuse new tenant-scoped cost, `OWNER_CLOSED`).

Dedupe and current-operation recovery continue: a redelivery or later revision whose original key maps (under the closure key) to a tombstone is recognised, rewritten to the tombstone and converges on the same record at closed-account scope, so a still-pending operation resolves once and the aggregate is never double-counted. Such a revision must carry the original tenant attribution or `platform/closed-account`; a different project, resource, owner or pool is `TENANT_MISMATCH`, a different task or an already-known provider ID is `IMMUTABLE_FIELD`, and a provider ID learned late (`null` → value) is still accepted. A producer may equally re-emit at platform closed-account scope with the same source ID (*Closed-account ingress* above). A genuinely new tenant-scoped event of a closed owner or project is refused (`OWNER_CLOSED`, `PROJECT_CLOSED`).

**Reports are not envelopes.** `exportHeads` returns a read record. After closure a `task`, `retry` or `control` head has `taskRef: null` and a `closed:` source ID, which `validateEvent` refuses as input, and it carries ledger-assigned `receivedAt`/`receivedSeq`/`lateAfterClose`. The contract promises no export-to-import round trip; WH-170 must not rely on one.

**What this is, and is not.** It is *pseudonymisation under a retained key*, not anonymisation. Without the closure key, nothing the ledger reports or stores can be tied to the owner, project, resource, task or provider record, and tombstones differ per key. With the key, anyone holding a candidate ID can confirm the link, and whoever holds both can recompute it. Occurrence timestamps, workload, placement label, quantities and costs also remain, which could single out a project when combined with outside knowledge. The reference holds the key in memory and has no key-destruction step; destroying the key would end the in-flight dedupe window and is a retention decision for WH-170 and the owner (decision 1), to be taken only after in-flight operations have resolved or expired. Until the key custody, its destruction time and the retention of the company totals and provider statements are decided and registered, this document makes no anonymisation claim, no statutory retention claim and no compliance claim.

## Source adapters (WH-169)

Status: **implemented as local source, not wired, not merged.** Evidence level: source library plus connected local fixtures on the current schema. It is not a ledger, an emission path or live acceptance.

**What it is.** `validateCostEvent(input)` enforces every rule of the *Envelope* table and returns an isolated copy, throwing `CostEventError` with the specific code at the first broken rule. The registries (`dimensions`, `workloads`, `sources`, `tariffs`, the reason/class/outcome/basis/pool/tier lists) are frozen module constants: there is no runtime registration and no registry argument, so a later packet registers its dimension, workload, tariff and adapter in one reviewed change to this module. `idempotencyKey({source, sourceEventId, dimension})` is the SHA-256 of the canonical (sorted-key) JSON of those three fields. The pinned tariff `pool-proposal@1` is the planning tariff of [`resourceTariff`](../src/resource-economics.ts), effective from September 30, 2026 (a Whumpo proposal, not an invoice).

**Adapters.** Each takes one row and returns a validated event; none reads or writes D1, a clock or the network. Rows are read by named column only, so text and customer figures cannot reach an event.

A pending (`reserved`, `dispatched`) or `uncertain` call is an explicit unknown quantity and cost whose `exposureMicros` is the reserved hold; it is never priced as zero or retried. A `released` call is known quantity `0`, cost `0` and no token detail. Every event has `customerUnits: 0`, and a premium event carries the provider cost only: the validator refuses any customer, debit, credit, price or invoice field.

**Choices.**

- **Asynchronous.** The digest is the Workers WebCrypto `crypto.subtle.digest('SHA-256', …)` used throughout `src/`, which is asynchronous, so `idempotencyKey`, `validateCostEvent` and the adapters return promises. The runtime has no Node `crypto` and no hand-written hash; the offline reference keeps Node's `createHash` as an independent oracle and the suite proves both produce the same bytes. WH-170 can compute the key before a transition batch because it depends only on `{dimension, source, sourceEventId}`.
- **Row validation before the envelope.** An adapter refuses a malformed row rather than repairing it: an unknown status is `UNKNOWN_STATUS`, an unknown `cost_basis` is `UNKNOWN_COST_BASIS`, and a missing, non-integer, negative, non-numeric or inconsistent figure (tokens or actual present on an unfinished call, absent on an observed one — the table's own `CHECK`) or a non-object row is `INVALID_RECEIPT`. An integer outside the safe range is `AMOUNT_UNSAFE`, never rounded. Envelope rules keep their codes (`INVALID_TIME`, `INVALID_ATTRIBUTION`, `TARIFF_NOT_EFFECTIVE`, …). `UNKNOWN_COST_BASIS` and `INVALID_RECEIPT` are adapter-level codes added by this packet; the envelope codes are unchanged.
- **Stricter than the reference in one place.** The reference tests `SAFE.test(c.ref)` and `SAFE.test(c.tariff.id)` without a type check, so a numeric reference or tariff ID is coerced and accepted. The source requires a string (`INVALID_COST`). The suite pins that this is the only disagreement; the frozen WH-168 reference is not edited.
- **The reference remains an oracle, not a dependency.** No `src/` file imports it and the product cannot (checked). The source registry differs from the reference in exactly one field: the three producer sources are `source-adapter` where the reference says `source-adapter-planned`.

**Gaps surfaced by writing the adapters (in addition to G-C1–G-C11).**

- **G-C12** The gateway adapter classes every attempt as `task` (matching the reference); the snapshot's `role` could be `ack`. Dispatch is inactive in live routing, so nothing is misclassified today.
- **G-C13** Which of `gateway_provider_receipts.event_id` and `log_id` is the preserved provider ID is not decided; the adapter takes whichever the caller passes. WH-170 must choose and keep it stable, because a provider ID once known is never replaced.
- **G-C14** `taskRef` is limited to 64 safe characters, `cost.ref` to 128, but the gateway routing layer accepts free labels up to 200 characters for `taskId` and the rate ID. A label outside the envelope alphabet makes the adapter refuse the attempt (`INVALID_EVENT`/`INVALID_COST`); nothing coerces it. Today's task IDs are UUIDs.
- **G-C15** `storage_project_usage` periods before September 2026 would be priced under a tariff not yet in force: the adapter refuses them with `TARIFF_NOT_EFFECTIVE` rather than invent a rate or an unknown-rate event. The table only admits the current month, so none exists.
- **G-C16** An unpriced call that is still pending carries the reserved hold (`0`) as a bounded exposure of `0`, as in the reference and the task-cost report, although its true cost is unbounded; the observed unpriced call is correctly unbounded.
- **G-C17** The tables update in place and keep no history (G-C3), so the adapters can only describe the row's *current* state. A transition that is never observed between two reads is never emitted; WH-170 must emit at each transition.
