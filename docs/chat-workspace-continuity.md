## Current source contract

Routine work belongs in Chat and its maintained panels. Saved pages are optional. Saved state, account/security/sign-out/support and urgent takedown/recovery must remain accessible without inference; generated layouts cannot own or hide those entry points. Server-owned project/task selection, domain handlers, review receipts and current identity admission remain authoritative. Current-only clients and schemas are required; no old-route adapters or data migrations are introduced.

### Reopening saved forms

The history dialog now searches and lists saved work; its second form editor is removed. Choosing a form closes the dialog and opens its current interaction in Chat. A form already in recent Chat is reused rather than rendered twice; an older form is rendered through the same component and current server read. The `interaction` query parameter is a strict UUID locator. It carries neither answers nor approval authority.

A per-tab `sessionStorage` record, `whumpo.chat-location`, uses the single current version 2 shape: authenticated account ID, target kind (`interaction` or `turn`), target ID and last explicit opening time. Superseded locator records are discarded without migration; form drafts and operation receipts are separate and unchanged. It expires after seven days without opening activity. Reading the stored locator does not renew its lifetime; explicitly opening a URL containing the locator counts as opening it. Malformed, stale-version, clock-rollback, expired and other-account records are removed. Existing account/sign-out cleanup clears it alongside Chat/form/photo recovery. Storage errors are visible; they do not pretend navigation has been saved.

This device locator has no model reader, server copy, PWA cache or export contents. The existing interaction API rechecks ownership, current admission, retention and project binding. It cannot select a different project, mutate answers, resume a model, upload a file or approve a review. URL navigation in another tab retrieves that tab's current server state; unsent local answers/composer text are not copied between tabs. Current draft and unresolved operation stores keep their original identities and retention rules.

**Close saved item** removes only the navigation locator. It never discards the form, answers or unresolved request. A form still in recent Chat remains there. Reopening an existing visible item refreshes current server state; removed or unauthorized work cannot become actionable through the saved locator.

### Reopening older messages, reviews and results

History messages have an **Open in Chat** control. It closes the history dialog and focuses the reopened message, using the same `ChatTurnEntry` presentation as recent Chat. Selecting a message already in the recent window removes its duplicate presentation. The strict `turn` UUID query parameter and the version 2 per-tab locator retain its location; repeated or simultaneous `turn`/`interaction` parameters are rejected as ambiguous. An invalid explicit link clears the remembered locator and displays an error instead of opening a different saved item. Closing clears only the location and returns focus to the composer. Unsent composer text remains separate, private to its tab.

`GET /api/chat/turns/:id` accepts one exact UUID without query parameters and returns `{version:1,turn}` with `no-store` headers. It shares the recent Chat SQL projection and existing domain/receipt readers, including exact reply hashes, current owned review validation and saved-result links. Website/service review and activation queries now use bounded groups of requested message IDs instead of the most recent 100 global links. The read requires current workspace identity and first-project admission; it rechecks the message bytes/status and current workspace authority after projection. A missing or removed message returns unavailable. Historical text is not permission to act; current domain handlers and explicit recent-proof approvals still govern effects.

The independently queried saved-message panel can load even when the recent conversation read fails. It hides prior content and controls while refreshing or after a failed read, and rechecks on window focus. Its private query is released when closed and cleared on account reset. Current pending message polling is read-only. Action results invalidate the saved projection so an applied review cannot retain its former approval button. Exact approval still uses the existing Chat transaction/retry identity and requires a current Chat revision; a total conversation outage does not grant a separate write path. Viewing, refresh, reload and navigation do not invoke inference, select a project, submit answers or approve work.

Local current-Worker/D1 acceptance covers an older website review after 105 newer linked reviews, service proposal/result/activation links, changed reply bytes, expiry, foreign/anonymous/unstarted access, message removal/change and identity loss during projection, and a private saved result after proposal cleanup. Existing feature admission remains domain-specific: an owned historical message can be readable while its current comparison or action is denied. This increment does not accept CMS functional journeys.
