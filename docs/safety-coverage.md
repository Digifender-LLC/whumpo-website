# Safety coverage and activation contract

**WH-010 — September 30, 2026. Source inspected at `a751852`.** This is an implementation inventory and a decision contract for the remaining gates. It is not a security scan, configured detector, legal determination or live safety acceptance. The [content policy](content-safety.md) remains authoritative: US-based customer admission, no sexual content, illegal activity/CSAM, piracy, scams/click fraud, hate/harassment or gambling; graphic violence alone is not a blanket ban.

CMS source was inspected for this map. **No CMS functional test, provisioning or customer operation was performed.** All described missing checks remain launch gates; the map does not enable them.

## Required identity and state

Before a protected action, the server must resolve an owned immutable target and its exact bytes. A future clearance binds:

`owner + project/subject + artifact kind + byte digest + context/manifest digest + policy version + required check set + scanner/version receipts + server validity/revocation state`.

The byte digest is SHA-256 of the **actual stored/served bytes**, not a client hash or R2 metadata alone. A normalization pipeline needs its version and original→normalized digest relation; scanning a thumbnail, another encoding or a previous version does not clear the delivered object. Text/code normalization must be explicit and deterministic; do not trim or rewrite source after scanning. A context digest binds action-relevant project intent, source provenance, selected dependencies, output destination/audience and authority revision. Context changes are new work; random request IDs/timestamps must not allow resampling identical work.

Separate four states:

1. **Stored:** upload/persistence finished; not safe to display, execute or publish.
2. **Triage complete:** bounded structural/static inspection finished; not an approval.
3. **Required checks clear:** every check selected by the server has a trusted, current, exact-target receipt. A missing check, unsupported format, timeout, integrity failure or inconclusive result keeps the action held.
4. **Action authorized:** content clearance plus the existing owner/visitor permissions, quotas and exact review/revision are valid at the final use boundary. A scanner cannot confirm publication, grant provider consent, release credits or authorize code execution by itself.

Holding content must preserve safe status/review/appeal access and critical unpublish/disconnect controls; it must not force the user to redispatch a potentially billable request or prevent reporting abuse. Deletion requests follow the separate preservation contract.

No model refusal, model-generated “safe” result, low risk score, financial Monitor mode, plan upgrade or purchased credit can grant clearance. Normal operator support access is not a quarantine viewing exemption. Restricted evidence inspection/reporting needs its separate authority and retention contract.

- Public images are `/assets/FILE.jpg`. CMS article/index/frozen-media and directory HTML/JSON have separate routes; gating the homepage does not gate them. GET **and HEAD** need the same admission. No-store headers reduce cached exposure but do not retract previously downloaded copies.

- Preview HTML can inline photos/CMS images; ZIP/JSON/transcript exports, diffs, saved reviews, backend-state snapshots, library nomination inspection, GitHub backups and restored versions are additional dissemination paths. A private bucket or authenticated owner does not automatically permit viewing suspected illegal media.
- R2 remains private. Never make a quarantine object public or route it through a public image URL to trigger a delivery-layer scanner. General remote-repository import, archive execution, arbitrary network dependency loading, videos and opaque binary uploads remain unavailable unless separately admitted with complete coverage.

## Mandatory versus supplemental work

**Always required:** private quarantine and exact ownership/integrity for imported source/media; every applicable media detector; bounded source/dependency checks; current format/capability eligibility; final artifact/dependency admission for publication/execution/export/serving; all outstanding required checks; existing exact human action reviews. A trusted platform component can reuse its immutable reviewed code evidence, but new customer text/configuration/inputs/assets retain their own requirements.

**Adaptive:** extra semantic/context inspection of ordinary Chat and generated work, based only on the reviewed risk history and stable selection. A low-risk landscaping project can avoid repeated supplemental scans of unchanged cleared work. It cannot skip mandatory media/import checks, cancel a selected check, or claim that an arbitrary new output is safe. Risk increases/current flags may strengthen requirements; subsequent decreases, key rotation, new request IDs and paid-tier changes cannot erase a pending requirement. Financial monitoring and this policy are independent.

**Legacy:** enumerate retained versions, profile/project photos, native CMS media/content, publication manifests, visitor documents, stored imports and external backup references. Missing clearance starts held at the protected boundary, not presumed clean. Profile/project media already have backfill holds; the other families do not. Plan coverage and owner messaging before broad rollout. Restore must reapply current denials/deletions; old database backups must not resurrect clearance, retired policy or withdrawn publication. Later matches require descendant/publication revocation and restricted incident handling, not ordinary automatic deletion.

1. **Provider contract (WH-011):** identify vetted private matching/classification providers, admitted formats/transformations, credentials/authority, terms/costs and exact result semantics. Separate known-CSAM matching from sexual-content detection; neither makes claims about all illegal behavior. 2. **Private media pipeline and CMS holds (WH-012/013):** trusted decoder and immutable target capture, durable dispatch/unknown-outcome reconciliation, signed/internal receipts, expiry, late-result handling and every S01–S05 read/preview/export/publication gate. Never add a customer-set `approved` flag.
3. **Import/generated work (WH-014):** converge direct import, pasted/model code and all version writers on exact admission. Add artifact/context manifests and final use checks for S06–S14; protect outputs as well as source. Confirm roadmap packet scope before implementation.
4. **Risk/incident operations:** connect trusted evidence intake without promoting refusals or visitor allegations to verified owner findings. Keep legal preservation/reporting and appeals in their dedicated roadmap work. No sampled “not required” result is an approval receipt.
5. **Acceptance matrix (WH-017):** benign fixtures only. For each path test wrong owner/digest/context/policy, stale review, missing check, expiry, concurrent replacement, detector outage, malformed/late/conflicting/replayed receipt, loss after commit and policy/revocation changes. Verify no general-model dispatch/QuickJS execution, raw-byte response, inline preview, export, external backup or publication occurs while held. Include direct API, Chat, both host aliases, GET/HEAD, restored artifacts and shared references. For dynamic apps include separate visitor/owner attribution and input→state→result/export paths. For CMS specify the fixtures now; keep feature acceptance paused until the owner changes that decision.

**Specific missing regressions:** CMS ready-but-unscanned media denial; raw WordPress download/analysis-before-clearance denial; pasted-source laundering through Chat/application builder; generated/static text clearance at preview/export/backup; expired/matched dependency withdrawing existing HTML and every alias; runtime-output/state clearance; imported archive/dependency bombs only when those formats are admitted; restore reapplying safety invalidation; trusted risk intake and correction propagation.
