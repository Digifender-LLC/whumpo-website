**Status: planned / audit. Dated 2026-10-11 UTC.** Baseline source is `d948f06` (origin/main when the audit started; origin/main later advanced to `8659e10`, and the only change to any audited frontend, server or test-helper file was `tests/helpers/current-database.mjs`). Nothing here is deployed, configured or customer-accepted. No remote operation, model call, provider call or schema change was made. This document does not complete WH-111 and is not WH-112 whole-experience acceptance.

[WH-111 / issue #100](https://github.com/zemdregon/whumpo/issues/100) already has a large delivered increment: [chat-workspace-continuity.md](chat-workspace-continuity.md) records it per increment. This audit does not restate it. It re-reads the current source against the five scope items and six acceptance criteria, reruns the evidence it cites, records what is still open, and splits the remainder into children (WH-206 to WH-213). Anchors are `file:line` against the baseline above. "Ran" means I executed the command in this audit on Node 24.21.0 and quote the result; "not run" means I did not.

## Method and limits

- Every "source does X" claim below cites a line I read. Behaviour that I could not establish from source is marked **unverified**.
- Two ad-hoc probes were run against the actual Worker (`src/index.ts`) and a disposable current-schema SQLite fixture. They were not committed. Their outputs are quoted where used. One became the new regression test `tests/chat-inference-outage.mjs`.
- Browser journeys ran with Playwright 1.63 (`WHUMPO_PLAYWRIGHT` pointing at an existing `playwright-core`) and headless Chromium on a 2 vCPU host. They use signed virtual passkeys, a built client, the real Worker and disposable current-schema D1. They are not physical-device, installed-PWA, human-listening or customer evidence.
- Not run: `tests/chat-screen-reader.mjs` (needs the isolated Orca speech sink), `tests/chat-interaction-browser.mjs`, any live-model suite, anything against Cloudflare, `pnpm check` (no TypeScript changed).

## What is on main today

**Navigation.** `workspaceView` makes `/workspace` the only Chat route and sends `/workspace/chat` and any malformed path to `missing` (`frontend/src/lib/workspace-navigation.ts:28-35`). Four fixed essentials (`saved-work`, `safety`, `support`, `security`) are a constant outside any generated layout (`:38-43`). A generated page named like a fixed control is shown as "Name (your page)" (`:54-57`). Desktop: Chat, Dashboard, generated pages, then a fixed "Help and account" group with the essentials and Sign out, then Settings and Profile in the footer (`frontend/src/workspace.tsx:154`; `frontend/src/mobile-workspace.tsx:40-45`). Mobile bar: Chat, Dashboard, Your pages, Settings, Help; Help opens a sheet with the four essentials, Profile and Sign out (`mobile-workspace.tsx:51-61`). The Dashboard, Settings, Profile and the control pages (project, cms, photos, inbox, records, domains, visitors, billing, connections) all remain routes (`frontend/src/workspace-pages.tsx:31-39`).

**Fixed identity-only surfaces.** `/workspace/security`, `/safety`, `/saved-work`, `/support` and `/operator-safety` are resolved before the profile read, so profile, Chat or Dashboard failures cannot block them (`workspace.tsx:54`). On the server, support is routed before the first-project gate (`src/index.ts:167-170`); Chat and every `/api/workspace/*` route are behind it (`:171`).

**Device state.** There is no `localStorage`, IndexedDB or Cache API use in `frontend/src` (`grep -rn localStorage frontend/src web` returned nothing; the only Cache Storage use is the four public offline files, `frontend/public/workspace-sw.js:6-11`). Everything else is `sessionStorage`, one tab at a time:
